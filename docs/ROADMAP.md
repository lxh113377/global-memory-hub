## 0. 读法

**双面分工。** 本文件是**公开面**：描述这个仓库要往哪走、以及凭什么算做完。用户私有环境里的记忆与技能台账是**私有权威**，本文件只登记聚合口径与指向，**不复制其内容**（隐私与商业信息红线）。

**只排依赖序，不排日历。** 里程碑只写「前置依赖 + 完成判据」，不写日期。理由是这个项目的推进速度受课业与外部依赖强烈影响，日历表会迅速作废，而依赖序不会。

**状态词。** `TODO` 未开始 / `WIP` 进行中 / `DONE` 已完成并已核验 / `BLOCKED` 卡在外部 / `UNVERIFIED` 取不到数。

## 2. 优先级排序

判据：**P0 = 公开上线链路 + 安全类**；**P1 = 功能补全与质量**；**P2 = 锦上添花**。同级别内按「阻塞他人」优先于「只影响自己」。

| 级别 | 任务 | 归位理由 |
|---|---|---|
| **P0** | G0 · G1 · G3 · G2 · G4 | 公开上线链路。G0 是前置（不修则远端一建即红），G1 是唯一需要人授权的一环 |
| **P0** | G5 | 安全：token 文件在 Windows 上实际未受保护 |

| **P2** | G8 · G11 · G14 | G8 依赖外部实测；G11 是体验打磨；G14 只是换个字符串 |
| **P1** | G31 | 交付面落后于已合并代码：按 README 下载的用户拿到的是不含 presets / export 的旧二进制，且 `SHA256SUMS` 能力从未在真实资产面跑通 |

| — | 盘面 B 两问题 | 属私有侧治理，与 A 面并行推进，不阻塞 |

- 紧急且重要：G1、G3（不做完，G2 永远起不来）
- 重要不紧急：G6、G7、G9、G10（决定产品的长期形状）
- 紧急不重要：G14、G5（都是小改动，但拖着会变成隐患）
- 不紧急不重要：G11

## 3. 后续工作计划

### 3.1 G0 — 已完成（记录，供后续复用）

**做了什么。** 两处缺陷：① 忽略规则把 `//go:embed` 的目标目录整个排除，干净克隆时编译期直接失败（本地因构建脚本先拷贝产物而永不暴露）；② 一条忽略规则用了 shell 的扩展通配写法，git 不支持，实测该规则**完全没生效**，导致构建产物呈半跟踪状态。

**怎么验证的。** 不用「本地能构建」推断。用 `git checkout-index` 把暂存面导出成一个等价的干净克隆，在导出目录里跑构建：

| 场景 | 结果 |
|---|---|
| 保留占位文件 | 构建 **rc=0** |
| 逆操作：删掉占位文件 | **rc=1**，报「目录内没有可嵌入文件」 |
| 还原占位文件 | 构建 **rc=0** |

第三行与第二行构成方向相反的一对，证明那个占位文件是**承重的**，不是装饰。另外冒烟了产物本体：版本号可读，能正确装载全部 9 个平台定义，且对未接入的平台如实报异常而不是静默通过。

**风险与应对。** 已发生的风险是「提交时漏项」：用路径参数限定的提交**静默丢弃**了已忽略路径上的删除，HEAD 树里那个文件仍在。靠 `git ls-tree` 复核发现并补了一笔。**应对：任何删除型改动提交后必须回读 HEAD 树，不能只看 `git status` 干净。**

### 3.2 G1 — 建远端（唯一需要人授权的一环）

> **状态：已完成（2026-10-01）**。私有建仓 → 首推 → 全历史扫描 → 转公开 → 公网匿名克隆并构建通过。
> **残余**：Release 资产尚缺，依赖 G10 的三平台交叉编译产物。

**步骤。** ① 定仓库可见性与仓库名；② 建远端；③ 首次推送；④ 打 Release 并把三平台二进制挂上去（依赖 G10 的构建产物）。

**所需资源。** 仓库托管账号的操作权限；G10 产出的交叉编译结果。

**风险。** 可见性一旦定错，历史里的任何内容都会随之暴露，而**改写已推送的历史属不可逆动作**。**应对：先私人建立、确认干净后再决定是否转公开**；转公开前跑一次全历史敏感串扫描（当前只扫过默认分支，全历史从未审过）。

### 3.3 G3 — 文档

**步骤。** ① 中文 README：问题、方案、三步上手；② 英文 README；③ 三平台安装说明，命令全部用占位符（不用任何个人绝对路径）。

**所需资源。** 无。命令蓝本可复用已有的一批按平台写好的安装说明（已在 2026-09-23 实机验证过），只需参数化改写。

**风险。** 文档里的命令「看起来对」但没在本机跑过。**应对：每条命令先在本机实跑，跑不通的不写进文档。** 另注意 Go 工具链不在 PATH（见 §3.10），文档必须写绝对路径兜底。

### 3.4 G2 — 双线部署

> **2026-10-14 实测校正**：主腿（GitHub Pages）已按下面的步骤 ①②③ 走完并验证可达；步骤 ③ 的镜像站从未建立，且它卡的是账号侧人工动作（AI 无 Cloudflare 凭证）。下列「风险」段保持原文有效 —— 本轮正是靠「两个域名各探一次 + DNS 对照」才把「镜像腿没做」和「本机访问不通」这两种状态分开的。

**步骤。** ① 前端构建；② 主站部署；③ 镜像站部署；④ 两侧逐文件哈希比对。

**所需资源。** 两个托管平台的账号与项目。

**风险。** 「部署命令成功」不等于「站点正确」。**应对：两侧产物逐文件哈希比对，且两个域名都要探一次 HTTP 状态；探不到就记不可达，不得写成「已核验」。** 注意两侧域名都存在时通时不通的历史（按「域名 × 时刻 × 通道」分别探测）。

### 3.5 G4 / G13 — 一致性

**步骤。** ① 落地公开仓与私有权威源的比对腿，只比「平台 id 集合」与「挂载形态」，路径字段豁免（两侧路径表示法必然不同，比必然不等）；② 对注入点不一致的端逐端实测，以实测为准回写。

**风险。** 比对腿写成「恒等」或「静默跳过」，看起来绿其实没测。**应对：两个方向各留一条腿——制造一次差异必须见红，制造一次相同必须见绿。**

### 3.6 G5 — token 权限

**步骤。** Windows 分支改为显式 ACL 收紧到当前用户；其余平台保持 filemode 语义。

**风险。** 收紧过头会让程序自己都读不了。**应对：改完实测「本用户可读 + 另一用户不可读」两侧。**

### 3.7 G6 / G9 — 控制台与服务缺口

**步骤。** ① 补四页与前端路由；② 补两个缺失接口；③ 中英双语。

**风险。** 前端引入新依赖后产物体积膨胀，被内嵌进二进制后二进制变大。**应对：设体积上限并在构建脚本里检查。**

### 3.8 G7 — 技能三档

**步骤。** ① 从原创条目中筛选；② 脱敏扫描（个人标识、绝对路径、私有项目名）；③ 门禁：可开源档必须扫零命中，上游引用档必须带来源链接，不公开档不得入库。

**风险。** 扫描漏项。**应对：扫描腿本身要有反向腿（故意注入一个敏感串必须见红）。**

### 3.9 G10 — CI

**步骤。** ① 三平台交叉编译；② 部署主站；③ 部署镜像站。

**风险。** 构建顺序错则 CI 必红（前端必须先构建、再构建 Go，因为 Go 侧内嵌前端产物）。

### 3.10 环境事实（会咬人的两条）

1. **Go 工具链不在 PATH。** 实测 `go` 命令不可直接调用，工具链位于固定绝对路径下（版本 go1.27.0 / windows / amd64）。本地构建脚本已在内部兜底，**CI 配置与安装文档必须同样兜底**。此项曾导致一次错误结论：早期只探测 PATH 就判「未安装」。
2. **git 的行尾转换开启。** 仓库以 LF 存储、检出为 CRLF，属该平台默认行为，接受。
