# FAQ

## 通用

### 它会上传我的东西吗

不会。程序不发起任何出网请求，没有遥测，没有后台常驻。权威库与备份都在 `~/.fenjue/` 下。

### 为什么只监听 127.0.0.1，不让我改成 0.0.0.0

改成 `0.0.0.0` 等于把你的记忆库暴露给整个局域网。本机程序一旦监听回环端口，**任何网页**理论上都能向它发请求，四道安全闸就是为了对付这件事。放开监听等于把这层防护的意义抹掉。需要远程访问时，走 SSH 端口转发。

### Windows 需要管理员权限吗

不需要。Windows 上刻意用目录联接（junction）而不是符号链接，正是为了避开开发者模式与提权要求。macOS / Linux 用符号链接，同样不需要。

### 支持哪些 Agent 平台

见 README 的平台矩阵。新增平台只需改 `platforms.json`，不用改代码。
标 `beta` 的平台表示已接入但**消费行为尚未实测验证**，请把它当预览用。

### `ga` 和 `beta` 有什么区别

`ga` = 挂载与消费行为都实测过。`beta` = 程序侧能挂，但**还没验证目标程序真的会读这个目录**。
宁可标 `beta` 也不提前宣称 `ga` —— 一个不工作的挂载比一个明确标注的预览更糟。

## 数据与安全

### 关闭某个平台会删掉我的东西吗

默认不会。默认是**软关闭**：保留链接、只停用注入，随时可恢复。
任何写操作前都会先备份，响应里回传备份号，控制台提供一键还原。

### 唯一例外是哪个平台

`cx`（Codex CLI）走物理镜像。它的「关闭」含义是**停止同步**，因为那里是真实拷贝而不是链接。
已经同步过去的文件不会被自动删除，需要你自己清理。

### 备份存在哪、会长多大

`~/.fenjue/trash/<备份号>/`，只增不改。每份备份带一个 `manifest.json` 变更清单。
长期不清理会累积，确认不再需要后自行删除对应备份号目录即可。

### 令牌会泄露吗

令牌每次启动重新生成，通过 URL **片段**携带。片段不会随请求发给服务器，也不会进入 Referer。
日志不打印令牌明文。仍需注意：任何能以你的用户身份读取 `~/.fenjue/token` 的进程都能拿到它，
本项目不防御已被同用户权限攻陷的场景（详见 [安全策略](SECURITY.md)）。

### 种子包里的东西会被篡改吗

播种前会做全量 SHA-256 校验（`manifest.json`），任何不符都在**写入之前**拒绝，一个文件都不会写。
校验有两套相互独立的实现，避免「实现与自己一致」造成的假通过。

## 使用

### 权威库已经有很多内容了，会被覆盖吗

不会。**零覆盖**是硬约束：已存在且非空的库，播种一律跳过。
所以你可以先把自己的记忆库放进去，再接入各 Agent。

### 某个平台的目录本身就是链接，会怎样

程序判定为「根已是链接」并**完全不碰**，直接跳过并如实报告，不会写穿链接。

### 我改了 `platforms.json`，要重启吗

命令行用 `--platforms` 指定时改完重跑即可。默认从仓库根自动定位。

### 新增平台要改代码吗

不用。只改 `platforms.json`，规约见 [贡献指南](CONTRIBUTING.md)。

### `verify` 子命令为什么有时候报 UNVERIFIED

因为那一侧**测不到**。UNVERIFIED 是独立于「通过」的状态，不折算为通过也不伪装成失败。
这比给一个说不清依据的「OK」更诚实。

## 开发

### 构建顺序为什么不能颠倒

Go 侧用内嵌指令把前端产物打进二进制，所以必须先构建前端。

### 我改了种子包内容，接下来做什么

跑 `python3 scripts/build_seed.py --manifest-only` 重算校验清单。
漏了这步，播种会在校验阶段 fail-closed 拒绝 —— 这是设计意图。

### 提交前必须跑什么

见 [贡献指南](CONTRIBUTING.md) 的「提交前必跑」。其中两条 `--selftest` 是为了验证判据本身会咬人：
没有反例腿的判据等于没有判据。
