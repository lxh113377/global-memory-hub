# Security Policy

## 本项目的安全立场

`焚诀 Global` 在你的机器上运行，并且**刻意监听一个本地端口**。这带来真实风险，因此安全不是附带功能，而是设计前提。

它承诺的边界：

- **只监听回环地址** `127.0.0.1`，不监听 `0.0.0.0`，局域网内其他机器无法直接访问
- **不联网、不上传、不放后台**：没有出网请求，没有遥测，没有后台守护
- 你的记忆与技能内容始终留在本机

## 安全模型：四道闸

本机程序一开，任何网页理论上都能向回环端口发请求。因此除健康检查外的所有接口都必须通过四道闸，任一不满足直接拒绝：

| 闸 | 作用 | 它挡的是 |
|---|---|---|
| **Host 头校验** | 只接受 `127.0.0.1:<port>` 与 `localhost:<port>` | DNS 重绑定（把域名解析到回环） |
| **来源白名单** | 只放行本站域名与显式 `--origin` 添加的来源 | 任意网页直连本地服务 |
| **CORS 预检应答** | 对白名单来源正确应答预检 | 浏览器侧跨域被拦导致功能不可用 |
| **访问令牌** | 除 `/api/health` 外全部要求；恒定时间比较 | 本机其他进程 / 其他网页直接调用 |

补充措施：

- 令牌每次启动重新生成，只在本机受限文件与终端打印的握手链接中出现
- 令牌通过 URL **片段**携带：片段不会随请求发给服务器，也不会进入 Referer
- 日志不打印令牌明文
- Windows 下对程序自身目录做 ACL 加固

## 已知限制（请认真读）

诚实说明能力边界，比声称万无一失更有用：

1. **能读你本机文件、能改你本机目录链接的进程，本身就是完全信任的。** 本项目不防御已被同用户权限攻陷的场景。它防的是「网页碰巧打到你」。
2. **令牌存在本机。** 任何能以你的用户身份读取 `~/.fenjue/token` 的程序都能拿到它。
3. **物理镜像平台（`cx`）的「关闭」是停止同步，不是删除。** 已经复制过去的文件不会被自动删除，需要你自己清理。
4. **软关闭保留目录链接。** 这是设计选择（可一键恢复），代价是链接仍然存在，只是不再注入内容。
5. **种子包随二进制分发。** 因此种子内容必须过门禁（无个人标识、无凭据、无危险命令）才允许入库；门禁本身带正反例自测。

## 报告漏洞

**请不要开公开 issue。**

用 GitHub 私密漏洞报告渠道：仓库页面的 `Security` 标签 -> `Report a vulnerability`。

请尽量包含：

- 复现步骤
- 涉及的平台（Windows / macOS / Linux）与版本号
- 你观察到的实际行为 vs 预期行为
- 是否涉及令牌、目录链接、备份内容

我们承诺：收到后 72 小时内给出初步回应（含是否受理的判断），受理后修复优先于新功能。

## 负责任的披露

- 给出合理修复时间后再公开细节
- 不进行 DoS、不触碰他人数据、不社工项目成员
- 说明已发现但尚未修复的问题时，请注明影响面

## 范围之外

以下**不属于**本项目的安全缺陷：

- 用户自行把 `--port` 暴露到局域网或公网（程序只绑回环，这是刻意的）
- 用户把权威库放在同步盘 / 版本库里，导致内容被第三方读取
- 用户自行修改 `platforms.json` 指向危险路径
- 第三方 Agent 程序自身的行为（本项目只负责把库共享给它，不控制它怎么用）
