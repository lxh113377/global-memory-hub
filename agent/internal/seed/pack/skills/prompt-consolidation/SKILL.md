# 提示词补丁层清理（Prompt Consolidation V2）

将经过多轮 append-only 补丁追加后变得臃肿的提示词文件，清理为按功能分章节、编号连续的干净版本，并通过 V1-V7 漏洞扫描确保清理过程未引入新的逻辑漏洞。每份文件独立处理，不跨文件合并。

## 适用场景

- 多轮迭代后积累了大量 `[以下为XX追加]`、`[补丁]`、`[vXX追加]` 等标记的提示词文件
- 文件体积臃肿，同一功能的规则散落在多处，阅读和维护困难
- 需要"瘦身"但不想丢失任何有效规则的场景
- 清理后需要确认未引入新漏洞（V1-V7 验证内建）

## 硬约束（不可违反）

1. **只做单文件清理，严禁跨文件合并**：每份文件独立读取、独立输出。跨文件合并会引入新的 V1-V7 漏洞，具体危害包括但不限于：
   - **角色边界破裂**：文件A定义"评分者"调用文件B的"执行者"，合并后两个角色混在同一文件中，调用链路失去方向性
   - **变量口径冲突**：文件A的评分公式用"自评分"，文件B用"审计分"，合并后同一变量指向不同口径（V3/V6 漏洞）
   - **降级策略错位**：文件A的超时降级指向文件C的 fallback 流程，合并后降级路径断裂（V4 漏洞）
   - **保护清单交叉污染**：文件A的"禁止删除"清单与文件B的"允许覆盖"规则冲突（V7 漏洞）

   **判定标准**：如果用户提供了多份文件，逐份独立处理，每份输出独立的 `_cleaned` 文件。绝不将两份或多份文件的内容合并到同一输出中。
2. **不修改规则实质语义**：只做结构重组和去重，不增删任何规则的实质内容。如果某条规则语义模糊，保留原文并在输出中标注 `[语义待确认]`。
3. **验证环节不可跳过**：必须完成 Grep 双验证（Step 5）和 V1-V7 扫描（Step 6）才算完成。如果本次清理涉及多份文件（逐份独立清理的场景），所有文件清理完毕后，**必须建议用户执行 `prompt-system-audit` 做跨文件深度审计**，确认文件间的引用关系（角色调用、数据传递、评分聚合）未因单文件结构重组而断裂。Step 6 的 V1-V7 扫描是单文件级别的快速检查，无法检测跨文件引用问题。
4. **备份原版**：在写入清理版之前，必须先备份原文件。

## 工作流

### Step 1: 文件接收与评估

1. 用户提供提示词文件路径（或直接将内容粘贴到对话中）
2. 读取全文，输出评估摘要：
   - 文件总行数 / 字符数
   - 检测到的补丁标记数量和类型（列出每种标记模式及出现次数）
   - 预估清理后可缩减的比例
3. 如果用户提供了多份文件，明确告知："将逐份独立处理，不跨文件合并。"然后按顺序依次处理每份文件。

### Step 2: 规则提取与去标记

1. 逐段扫描全文，识别并提取所有**实质性规则内容**（排除纯标记行和空行）
2. 去除所有补丁标记，包括但不限于：
   - `[以下为XX追加]`、`[以下由XX补充]`
   - `[补丁 vXX]`、`[vXX 追加]`、`[vXX 补丁]`
   - `[追加规则]`、`[新增]`、`[补充]`
   - `[重要补充]`、`[关键修正]`
   - `[以下为审计后追加]`、`[审计补丁]`
   - `[由XX建议追加]`、`[XX建议的修复]`
   - 任何 `[]` 或 `【】` 内标注来源/版本/追加者的标记
3. 识别重复规则：同一功能在不同补丁中重复出现的，保留最完整版本，删除旧版本
4. 识别矛盾规则：如果不同补丁对同一事项有矛盾描述，保留较新版本，在输出中标注 `[原文存在矛盾，已取较新版本，见备份原版 line XX]`

### Step 3: 按功能分章节重组

将提取的规则按功能逻辑分类，每个章节统一编号。常见功能分类：

1. **角色定义与职责** — 该角色的身份、核心职责、权限边界
2. **工作流与执行步骤** — 具体执行流程、阶段划分、步骤编号
3. **调用规则** — 调用其他角色/工具的方法、参数、条件
4. **评分与门禁机制** — 评分公式、门禁阈值、通过/不通过判定
5. **降级与异常处理** — 超时处理、失败降级、异常情况的 fallback 方案
6. **输出格式规范** — 输出结构、模板、字段要求
7. **保护规则与禁止项** — 不可执行的操作、安全约束、红线规则
8. **跨文件数据传递** — 读写外部文件、数据格式约定、接口契约
9. **其他** — 不属于以上分类的零散规则

根据文件实际内容灵活调整分类，不强制每个分类都要有内容，也可以根据需要细分出新的分类。

### Step 4: 写入清理版

1. 将重组后的内容写入清理版文件
2. 命名规则：原文件名 + `_cleaned` 后缀（如 `agent_a.md` → `agent_a_cleaned.md`）
3. 写入位置：与原文件同目录
4. 格式要求：
   - 每个章节有清晰的 `##` 标题
   - 章节内规则连续编号（1.1, 1.2, 1.3...）
   - 保留原文的 markdown 层级结构
   - 在文件头部添加清理元信息注释：

```
<!-- 
  清理版本 | 原文件: xxx.md | 清理时间: YYYY-MM-DD
  原文件行数: XXX → 清理后行数: YYY | 缩减比例: ZZ%
  去除补丁标记数: N | 合并重复规则数: M
-->
```

### Step 5: Grep 双验证

**必须完成以下两项验证，缺一不可。**

#### 5a. 补丁标记残留检查

对清理版文件执行 Grep 搜索，确认无补丁标记残留：

```
Grep pattern: \[.*(追加|补丁|补充|新增|修正|建议|audit|patch|append|added).*\]
目标: 清理版文件
期望结果: 0 matches
```

如果发现残留，立即修复后重新验证。

#### 5b. 规则覆盖完整性检查

将原文件中所有实质性规则（不含标记行）与清理版逐条比对：

1. 从原文件中提取所有包含实质内容的段落/规则条目
2. 在清理版中搜索每条规则的关键短语（取每条规则的前10个关键字作为搜索词）
3. 确认每条规则在清理版中都有对应内容
4. 如果发现遗漏，立即补充到清理版对应章节，然后重新验证

验证完成后输出验证报告：
```
Grep 验证结果：
- 补丁标记残留: 0 (通过)
- 原文件规则总数: XX
- 清理版覆盖: XX/XX (100%)
- 遗漏规则: 无
```

### Step 6: V1-V7 漏洞快速扫描

**对清理版文件执行 7 类漏洞检查，确保清理过程未引入新漏洞。此步骤不可跳过。**

**漏洞来源判定标准**：对每个发现的漏洞，必须通过 Grep 原文件确认其来源：
- 如果原文件中已存在同一问题（Grep 原文件能匹配到相同的漏洞模式），标注为 `[原文已有，非清理引入]`——记录但不修复，因为这不属于清理引入的新问题
- 如果原文件中不存在但清理版中出现（Grep 原文件无匹配），标注为 `[清理引入，需修复]`——必须立即在清理版中修复
- 如果原文件中有相关内容但清理重组后语义变得模糊或丢失上下文，标注为 `[清理退化，需修复]`——必须修复，补充缺失的上下文

逐项扫描，每项输出 ✅ 或 ⚠️ + 发现问题数：

#### V1: 角色调用方法是否具体

检查清理后是否丢失了具体的调用方式（CLI命令、API端点、skill名称）。
- **Grep**: `发给/委托/通知/调用/传给/交给`
- **检查**: 每个匹配行是否仍伴随具体命令或操作路径

#### V2: 线性工作流是否有强制门禁

检查清理重组后"不可跳过/缺一不可"等强制性声明是否完整保留。
- **Grep**: `步骤/流程/然后/接下来/→`
- **检查**: 关键步骤是否有"不可跳过/必须/缺一不可"声明

#### V3: 评分公式是否无歧义

检查公式变量定义是否在清理中被截断或丢失上下文。
- **Grep**: `min/max/avg/分数/评分/得分/公式/综合/取`
- **检查**: 每个公式的变量来源是否唯一、聚合方式是否明确

#### V4: 超时/失败降级处理

检查降级策略是否在清理中被误删（原补丁中的降级方案可能被误判为冗余）。
- **Grep**: `等待/读取/调用/依赖/加载`
- **检查**: 是否有对应的"否则/失败时/超时时/不存在时"降级语句

#### V5: 跨文件数据传递是否明确

检查文件路径和容错策略是否在清理中完整保留。
- **Grep**: `读/参考/引用/加载/先读/上一轮`
- **检查**: 是否伴随具体路径和容错定义

#### V6: 历史分数锚定是否指明来源

检查分数来源口径是否在清理中丢失。
- **Grep**: `上一轮/上轮/R\d+.*分/基线/锚定/历史.*分`
- **检查**: 每处引用是否明确标注了分数来源口径（自评/审计/双门禁最低）

#### V7: 保护/禁止规则是否附具体清单

检查保护对象的具体清单是否在清理中完整保留。
- **Grep**: `不可删除/禁止/保护/不可修改/受保护/不允许`
- **检查**: 每处声明是否伴随具体对象清单或查询方式

**V1-V7 扫描输出格式**：
```
V1-V7 漏洞扫描结果：
| 类型 | 状态 | 发现问题数 | 说明 |
|------|------|-----------|------|
| V1 角色调用 | ✅/⚠️ | {n} | {具体问题} |
| V2 强制门禁 | ✅/⚠️ | {n} | {具体问题} |
| V3 公式歧义 | ✅/⚠️ | {n} | {具体问题} |
| V4 超时降级 | ✅/⚠️ | {n} | {具体问题} |
| V5 数据传递 | ✅/⚠️ | {n} | {具体问题} |
| V6 锚定分数 | ✅/⚠️ | {n} | {具体问题} |
| V7 保护清单 | ✅/⚠️ | {n} | {具体问题} |
```

**如果发现漏洞**：直接在清理版中修复，然后重新执行 Step 5（Grep 双验证）确认修复未引入新问题。修复后在最终摘要中标注 `[V1-V7 修复: {漏洞编号}]`。

### Step 7: 备份原版 + 最终摘要

1. 将原文件备份到工作目录：`原文件名_backup_YYYYMMDD_HHMMSS.md`
2. 告知用户备份位置
3. 输出最终清理摘要：

```
清理完成：
- 原文件: xxx.md (XXX行, YYKB)
- 清理版: xxx_cleaned.md (XXX行, YYKB)
- 缩减: ZZ%
- 去除补丁标记: N处
- 合并重复规则: M条
- V1-V7 扫描: 全部通过 / 发现X处问题已修复
- 备份位置: /path/to/backup
```

## 补丁标记识别清单

以下为常见的补丁标记模式，清理时需要识别并去除：

| 模式 | 示例 |
|------|------|
| `[以下...追加]` | `[以下为审计后追加]` |
| `[补丁 vX.X]` | `[补丁 v2.1]` |
| `[vX.X 追加]` | `[v3.0 追加]` |
| `[追加规则]` | `[追加规则] 评分时...` |
| `[新增]` | `[新增] 降级策略...` |
| `[补充]` | `[补充说明]` |
| `[重要补充]` | `[重要补充] 当超时...` |
| `[关键修正]` | `[关键修正] 原公式...` |
| `[审计补丁]` | `[审计补丁 V3]` |
| `[由XX建议...]` | `[由Codex建议追加]` |
| `[XX追加的修复]` | `[WorkBuddy追加的修复]` |
| `【XX追加】` | `【审计后追加】` |
| `> [!note] 补丁` | Callout 形式的补丁标记 |

如果文件使用了非标准标记，根据上下文语义判断是否为补丁标记。

## 验证检查项

清理完成后，用以下清单做最终检查：

1. 清理版文件中无任何 `[...]` 或 `【...】` 形式的补丁来源标记
2. 原文件每条实质性规则在清理版中都有对应（通过 Grep 关键短语验证）
3. 章节编号连续无断裂
4. 规则编号在各章节内连续
5. 无悬空引用（如"见上方补丁"、"参见v2.1追加部分"等指向已删除标记的引用）
6. V1-V7 漏洞扫描全部通过，或已发现问题已修复
7. 原文件已备份
8. 清理版文件头部的元信息注释准确

## 与其他技能的配合（决策树）

清理完成后，根据以下决策树判断是否需要联动其他技能：

```
清理完成
├── 只清理了 1 个文件
│   └── Step 6 V1-V7 快速扫描通过 → 完成，无需额外操作
│
├── 逐份清理了多个文件
│   ├── 所有文件各自 V1-V7 通过
│   │   └── → 建议执行 `prompt-system-audit` 做跨文件深度审计
│   │         （确认文件间的角色调用、数据传递、评分聚合引用未断裂）
│   └── 任一文件 V1-V7 发现 [清理引入] 漏洞
│       └── → 先修复，再执行 `prompt-system-audit`
│
└── 清理涉及文件路径变更或角色调用方式调整
    └── → 额外执行 `A-skill-manager`
          （同步修复数据层：死链引用、注册表 orphan、路径漂移等）
```

**关键区别**：本技能的 V1-V7 扫描是**单文件级别的快速检查**（聚焦"清理是否引入了新漏洞"）。`prompt-system-audit` 是**跨文件级别的深度审计**（含角色关系图构建、漏洞定级、修复补丁生成、数据层 D1-D6 验证）。两者互补，不替代。

```markdown
[以下为审计后追加]
```

```markdown
3.2 权重取值范围为 0.5-1.5，默认 1.0

```
