# 修完验证 — 5 步 Gate + 3 次熔断（debugging-fixing 分卷）

> 抄 `verification-before-completion`（Gate Function + Common Failures）与
> `systematic-debugging` Phase 4（3 次失败转架构评审）。主文件只留独立节指针。

## 5 步 Gate（断言前必走，跳步 = 虚报）

```
断言任何状态前：
1. 定命令：哪条命令能证明这个断言？（测试/构建/lint/复现脚本，写出全命令）
2. 跑全量：执行完整命令（fresh，不用缓存/片段/上次输出）
3. 读输出：读完全部输出，记退出码与失败数
4. 对证据：输出真能推出断言吗？（"应该能过" ≠ 过；部分绿 ≠ 全绿；agent 说成功 ≠ 成功）
5. 再断言：证据齐了才开口；否则如实报实际状态 + 证据
```

## 常见虚报对照

| 你想说 | 必须先有 | 以下都不算数 |
|---|---|---|
| 测试全过 | 测试命令输出 0 失败 | 上次跑过、应该能过 |
| 构建成功 | 构建命令 exit 0 | lint 过了、看着像成了 |
| 缺陷修好 | 原症状复现脚本变绿 | 代码改了、想当然好了 |
| 无回归 | 全量测试仍绿 | 只跑了单文件 |
| agent 办成了 | VCS diff 见改动 + 独立复验 | agent 回报"成功" |

## 3 次熔断（抄 systematic-debugging Phase 4.5）

- 修 1-2 次没好：回第 1 步重析（带上新信息），不许连试第 3 次同样的路。
- 第 3 次仍失败：**停手，质疑架构**——每次失败冒出不同位置的新问题 / 要"大重构"才能修 / 修好 A 坏 B = 架构错了，不是假设错了。
- 第 4 次动手前必须与人讨论（换架构还是继续），不许静默再试。

## 红线（命中即停手回第 1 步）

- "这次先快速修一下，稍后补测" / "改两处一起验证省时间" / "肉眼看过了" / "再试一次"（已败 2+）/ 不读输出就断言。
